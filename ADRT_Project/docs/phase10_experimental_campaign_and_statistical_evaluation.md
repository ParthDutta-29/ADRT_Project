# Phase 10: Experimental Campaign & Statistical Evaluation

This document details the transition of the ADRT framework into a **statistically evaluated, experimentally validated, publication-oriented cyber-physical resilience research platform.** 

The framework is academically positioned as: *"A bounded stochastic cyber-physical resilience abstraction framework for tractable SMC experimentation of attack-defense-response-recovery dynamics under operational uncertainty."*

## 1. Formal Experimental Campaign

A rigorous experimental campaign has been formalized inside `validation/experimental_queries.q`. The suite evaluates five critical research axes:
*   **A. Resilience Evaluation:** Measures graceful degradation bounds, safe-mode transitions, and survivability probabilities against specific attack configurations.
*   **B. Congestion Analysis:** Evaluates mitigation delays, firewall queue saturation (`fwQueueSize > 80`), and latency-induced collapse dynamics.
*   **C. Stealth Persistence:** Determines adversary survival under degraded telemetry bounds.
*   **D. CPS Instability:** Assesses the translation of cyber latency into physical control anomalies (`processDeviation`, `controlLatency`).
*   **E. Sustainability Tradeoffs:** Formalizes analysis of environmental (`carbonCost`) and operational (`energyCost`) overhead generated by mitigation efforts.

## 2. Parameter Sensitivity & Reproducibility Support

The framework now natively supports highly reproducible bounded parameter sweeps without triggering unbounded infinite-dimensional state explosions:
*   **Automation Toolkit:** `scripts/experiment_runner.py` automatically sweeps abstract parameters (e.g., `mitigationCapacity [20, 50, 80]`).
*   **Configuration Management:** Sweeps are driven by JSON metadata (`config/experiment_sweep.json`), ensuring absolute traceability.
*   **Stochastic Iteration:** Uses `simulate N` syntax natively within UPPAAL SMC to generate standard confidence intervals and statistical distributions over bounds (e.g., Mean `restorationConfidence` across 100 iterations).

## 3. Statistical Evaluation & Result Interpretability

Statistical outcomes from the SMC verifyta traces map to formalized operational interpretations:
*   **High `congestionPressure`** → Direct manifestation of mitigation saturation risk.
*   **High `controlLatency`** → Direct manifestation of delayed CPS stabilization.
*   **High `carbonCost`** → Environmental sustainability degradation tracking prolonged defensive engagements.
*   **High `resilienceDegradation`** → Objective failure of the survivability envelope bounds.

This allows statistical outputs to natively translate to publication-ready domain insights.

## 4. Scalability & Computational Analysis
The framework preserves total modular verification tractability.
*   By abstracting complex continuous systems (e.g. queuing theory, physics ODEs) into `int[0,100]` probability-scaled bounded assignments, execution scales safely.
*   Experiment generation avoids deep backtracking traps through stochastic bounds clamping and forward-progress guarantees (bounded recovery operations).

## 5. Visual Generation Support
A publication-oriented plotting script (`scripts/plot_results.py`) has been embedded into the framework. It translates bounded SMC trace datasets into academic figures, explicitly focusing on:
*   Sustainability Tradeoff Curves (Carbon Cost vs. Mitigation Capacity).
*   Resilience Degradation Envelopes (Survivability degradation bounds mapped over simulated execution time).

## 6. Expanded Experimental Threats to Validity
The existing threats-to-validity documentation has been structurally expanded for experimentation:
*   **Stochastic Validity:** Probabilities are relative weights, simplifying the infinite continuous variance present in real industrial systems.
*   **Experimental Realism:** There is no exact empirical packet calibration; testing relies on parameter boundary stress rather than precise playback of network PCAPs.
*   **Computational Generalization:** The specific topology (water treatment abstraction) hardcodes failure propagation logic that would not directly map to mesh-based grid networks without manual structural reconfiguration.

## Future Requirements
Publishing this framework at top-tier CPS security venues requires executing these defined parameter sweeps against a high-performance compute node, processing the simulated output using the provided visualization suite, and mapping the theoretical bounds against isolated empirical testbed metrics to confirm the trajectory curves.
